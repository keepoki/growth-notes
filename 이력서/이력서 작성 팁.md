## 이력서(Resume) 작성 기법: '가독성'과 '수치화'

이력서는 인사담당자가 6~10초 내에 훑어보는 문서입니다. 핵심이 즉시 눈에 들어와야 합니다.

- **역순 배치 (Reverse Chronological):** 가장 최근의 경력과 학력을 가장 상단에 배치하세요. 현재의 역량이 가장 중요하기 때문입니다.
- **숫자로 증명하기 (Quantify):** "매출 증대에 기여함" 보다는 **"전년 대비 매출 15% 상승 달성"** 처럼 구체적인 수치를 사용하세요.
- **직무 키워드 활용:** 채용 공고에 나온 핵심 역량 단어들을 이력서 곳곳에 녹여내세요. (예: 데이터 분석, 협업, Python 등)
- **불필요한 정보 제거:** 직무와 관련 없는 가족 사항, 키, 몸무게 등은 과감히 삭제하고 직무 역량에 집중하세요.

### 이력서 작성 전략

### 1. 기술 스택(Tech Stack)의 구체화

단순히 기술 이름을 나열하는 데 그치지 말고, 각 기술을 **어느 정도 수준으로, 어떻게 활용했는지**를 한 줄로 덧붙이는 것이 좋습니다.

- **Bad:** React, Next.js, TypeScript
- **Good:**
    - **React & Next.js:** SSR/SSG를 활용한 SEO 최적화 및 Lighthouse 성능 점수 개선 경험
    - **TypeScript:** 인터페이스와 제네릭을 활용한 타입 안정성 확보 및 런타임 에러 최소화
    - **CSS/TailwindCSS:** 디자인 시스템 구축 및 반응형 웹 디자인 구현

하지만, 면접 때 해당 기술에 대해 제대로 설명하지 못한다면 나열하는 것이 나을 수도 있음.

### 2. 프로젝트 경험: '무엇'보다 '어떻게(How)'

개발자에게 가장 중요한 것은 **'사용자 경험(UX) 개선'**과 **'성능 최적화'**입니다. STAR 기법에 맞춰 다음 내용을 포함해 보세요.

- **성능 최적화 경험:** "Next.js의 Image 컴포넌트를 도입하여 LCP(Largest Contentful Paint)를 1.5초 단축함", "Code Splitting을 통해 초기 번들 크기를 30% 감소시킴"
- **협업 효율성:** "Git Flow를 도입하여 팀원 간 코드 충돌 해결 및 리뷰 문화 정착", "Storybook을 활용해 디자이너와 컴포넌트 단위 협업 효율 증대"
- **문제 해결 능력:** "React Query 도입으로 복잡한 API 상태 관리 로직을 간소화하고 데이터 캐싱을 통해 서버 부하 감소"

### 3. 결과물 증명 (Portfolio & Link)

프론트엔드는 눈에 보이는 결과물이 중요합니다.

- **GitHub:** 단순 과제가 아닌, 고민의 흔적이 담긴 커밋 로그가 중요함 (Readme.md를 잘 작성해야 함!)
- **배포 링크:** 실제 작동하는 결과물을 볼 수 있는 Vercel, Netlify 등의 배포 링크를 첨부할 것
- **블로그:** 기술적인 고민이나 트러블슈팅 과정을 기록한 블로그가 있다면 큰 가산점이 된다.

### 4. 이력서에 넣으면 좋은 프론트엔드 핵심 키워드

- **상태 관리:** Redux, Recoil, Zustand, React Query 중 본인이 강점 있는 도구 기술
- **테스트:** Jest, Cypress를 이용한 테스트 코드 작성 경험
- **웹 표준/접근성:** 시맨틱 마크업(HTML5) 준수 및 웹 접근성 개선 경험

### 작성 예시 (경력/프로젝트 상세 중 일부)

> **프로젝트명: OOO 커머스 플랫폼 고도화**
> - **역할:** 프론트엔드 메인 개발 (Next.js, TS)
> - **주요 성과:**
>     - Next.js의 ISR(Incremental Static Regeneration)을 적용하여 동적 상품 페이지의 로딩 속도를 기존 대비 40% 개선.
>     - 반복되는 UI를 공통 컴포넌트화하여 개발 생산성을 2배 이상 향상.
>     - TypeScript 적용으로 개발 단계에서 타입 오류를 90% 이상 사전 차단하여 서비스 안정성 확보.
